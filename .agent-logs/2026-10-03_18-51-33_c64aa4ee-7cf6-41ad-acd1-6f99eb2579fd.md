## Summary

**Can it be built with no additional cost?** Yes — as a **stylized, browser-native** story agent that keeps Cutroom's existing offline/mock philosophy. No paid APIs, no paid hosting. The free stack:

- **Script** → seeded story-grammar/templates (optional in-browser WebLLM)
- **Frames** → the existing procedural scene generator + a canvas timeline
- **Voice in selected language** → Web Speech API (free OS voices)
- **Lip sync** → viseme-driven animated avatar from TTS `onboundary` timing
- **Subtitles** → timed overlay + downloadable `.vtt`, localized

The two honest limits I flagged in the doc: it's an **animated narrator, not photoreal face reanimation**, and a fully-**baked downloadable file** is staged as P1 (browsers won't capture `speechSynthesis` audio directly — `ffmpeg.wasm`/Piper-WASM solves it, still $0 but with a one-time WASM download). In-browser playback itself is fully free.

**The document** — [Docs/STORY-AGENT.md](Docs/STORY-AGENT.md) — follows your existing [WORKSTREAMS.md](Docs/WORKSTREAMS.md) pattern and divides the feature into two parallel halves behind a frozen `StoryTimeline` contract:

- **Half 1 — Story Engine & Timeline** (headless): prompt → beats → scenes/dialogue, timing to hit ~3:00, localization, subtitles, cost quote, store wiring. No DOM.
- **Half 2 — Stage, Lip-Sync & Export** (the player): canvas scene player, Web Speech narrator, viseme avatar, subtitle overlay, transport, and optional export.

It includes a capability-by-capability cost audit, the parallelism/stub plan, shared-file ownership rules, and a suggested sequencing table — all mirroring how the repo already splits UI → store → engine.
